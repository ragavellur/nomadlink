SPRINT-001 — Foundation, safety and de-risking

Make the repository trustworthy as the source of truth, remove the credential leak risk, and run the three blocking hardware experiments that determine whether the product's headline features are feasible at all.

Why these tasks

Rationale
TASK-004 is first because tracker/tracker.ino contained a hardcoded broker credential. Committing that file before fixing it would have put a live secret into git history. The code side is now done and verified across full history; only the broker-side rotation remains, which is a human action.
TASK-019 is the framework decision and it blocks the entire network epic (TASK-101, TASK-103, TASK-104, TASK-108 to TASK-110). Its stated precondition - prove PPP works on this board - is now satisfied, so this is the highest-value task left in the sprint.
TASK-020 is complete: PPP negotiates to phase RUNNING and yields a real IP. See BUG-006 for the three defects that had to be fixed and LESSONS_LEARNED L-11/L-12 for the diagnosis traps.
TASK-021 remains blocked on a physical inspection of the board. No amount of code can settle whether the I2S mic and amp are populated.
TASK-301, TASK-303 and TASK-405 are deliberately NOT in this sprint even though they are P0, because each depends on TASK-019's outcome or on TASK-001/004 completing first. TASK-405 is the natural next sprint: nothing blocks it and it produces the first real end-to-end publish.

Deliberately out of scope this sprint

Any NAT routing code (blocked on TASK-019)
Any web portal work (integration surface, but the framework choice is unresolved)
ESP-SR / voice (blocked on RISK-003)
